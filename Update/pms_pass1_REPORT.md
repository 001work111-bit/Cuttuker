## Решения, реализованные по ТЗ

- Идентичность варианта: `tpl|format`. Разные аспекты одного шаблона — разные варианты. При коллизии `id` добавляется суффикс формата (`…_9x16`).
- `styleSystem` — принадлежность к стилям. Один вариант в двух стилях — одна карточка.
- Конфликт: при разном HTML или значимых метаданных (`label`, `group`, `code`, `desc`, `kind`, `single`, `adaptation`, `motionStudio`, `sandboxMeta`) обе версии сохраняются с источниками, карточка помечается, спорная версия не применяется. Выбор — явный, через подтверждение. Приоритет по имени файла или времени не вводился; основная версия — уже применённая (`_primaryFp`).
- Повторная загрузка того же источника: записи на месте, стилевые связи сохраняются, отчёт «без изменений».
- Ошибка одного файла: отчёт с ошибкой, библиотека сохраняется.
- `user.js` при обновлении пропускается (защищённый слой).
- Обновление не трогает `project` без `templateLibrary` (проверяется сравнением снимка проекта).
- JSON-импорт: выбор существующего стиля или создание нового; назначение только импортированным вариантам.

## Ограничения и известные особенности

- Удаление файла из `templates/` не удаляет его записи из галереи (только обновление существующего файла вычищает его старые записи). Это сознательно, чтобы не потерять данные при ошибке чтения.
- Отпечаток — FNV-1a×2 + длина, не криптографический; коллизия маловероятна, но не исключена.
- Выбор стиля при JSON-импорте — через `prompt` (минимальный диалог), не через отдельную форму.
- Конфликты разрешаются по одному через `confirm`; интерфейса сравнения версий нет.
- Первое обновление после автозагрузки отчитывается как «изменено» (записи получают `sandboxMeta`); последующие обновления без изменений — «без изменений».
