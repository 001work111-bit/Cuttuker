# Sandbox v9 — финальный корректирующий проход: отчёт

Область: только Sandbox (рабочая копия `work_v9/Sandbox_9x16_fix/`). PMS не менялся. Ядро адаптации, алгоритмы методов и геометрия не менялись.

## 1. Что изменено

**Интерфейс (части I–II)**
- `library-audit.js` (переписан): кнопка «Проверка библиотеки» (`#btnLibAudit`) — квадратная синяя, белая контурная иконка карандаша, без текста, `title` и `aria-label` «Проверка библиотеки»; переключение список ↔ инспектор.
- Три независимых состояния: базовая выборка (`tplPassesBase`, обычные фильтры Sandbox), дополнительная выборка по типу проблемы (`window.SB_inspFilterIds`), рабочее выделение (`checked`). `tplPassesFilters` = базовая + дополнительная; галерея «Карта» использует тот же предикат.
- Записи проблемных шаблонов свёрнуты по умолчанию; переключатель `.li-tog` с `aria-expanded`, мышь и клавиатура.
- Категории A/B/C с причиной, влиянием, рекомендацией и действиями. Неоднозначные (C) не исправляются автоматически. Удаление — только структурных записей, с подтверждением и очисткой связей (`delTpl`-логика: S2_CONV, IMG_ASSIGN).
- Пересоздание устаревшей конверсии (A) — как новый шаблон через `RC_recreateOutdated`; исходник и существующая конверсия не меняются.
- Сообщение о результате пересоздания теперь называет созданный шаблон (раньше показывало ID исходника). Для этого `rcCreate` возвращает `report.created` / `report.changed`.

**Нейросеть (части III)**
- `library-repair.js` (новый, `window.SB_repair`): пакет `sandbox-repair-package` (`targets[]` с полной записью, проблемами, диагностикой, адаптацией, исходником; `styles`, `batches`, `contract`, `task`, `returnFormat`, `expectedTpl`). Без выбора кнопка отключена.
- Импорт: `validateReturn` — структурные ошибки (не JSON, не массив, лишние/дубли/пропущенные ID) → ничего не заменяется; поштучная проверка (обязательные поля, `tpl`, число `data-sb-editable` и медиа-слотов, структурные проверки, устранение прежних проблем) — провалы отклоняются поштучно. `applyReturn` — резервная копия скачиванием, `pushUndo`, сохранение `styleSystem`/`batch`.
- Отчёт и «Скопировать отчёт для нейросети».

**Откат (VI.10)**
- `restoreState` выполняет каждую группу изолированно и собирает ошибки; `verifyUndoGroups` сверяет фактическое состояние со снимком по 11 группам (LIB, BATCHES, STYLES, S2_CONV, IMG_ASSIGN, IMG_MODE, NORM_BACKUP, PROMPTS, PFOLDERS, HOTKEYS, builderCfg).
- Сообщение: «Отменено: откачено групп — N» только при полном откате; иначе «Откат неполный. Не восстановлено: …». То же для повтора.

**Формат (VI.11)**
- Неизвестный/не заданный `aspect` → «Формат не определён» (исправлена строчная буква). Подстановки 16:9 нет.

**Капсулы (IV.7)** — CSS уже соответствовал ТЗ (одинаковая высота 24px, пилюли, серые неактивные, синий активный); подтверждено в браузере.

**motion-converter.js (VI.12)**
- `compatMotion`: совместимые поля `source.motion` сохраняются; пересчитываются только `contract`, `aspect`, `canvas`, `entities`; `animation` из исходника сохраняется.
- Дедупликация по `tpl`: точный дубликат (тот же HTML и aspect) объединяется только при совпадении `canvas`; конфликт `canvas` — предупреждение, второй экземпляр пропущен; разный HTML/aspect одного `tpl` — предупреждение, сохраняется первый.

**Методы для форматов (V.8)**
- `module.json` четырёх методов (`smart`, `compact`, `split`, `fit`) возвращены к состоянию предыдущего ZIP: `targetFormats` = `16:9, 9:16, 1:1, 4:3`. В рабочей копии были обнаружены `4:5`/`5:6` без решения владельца — откатил (см. раздел 4).

**Реестр форматов (VI.13)** — `SB_FORMATS` и `RecomposeCore.FORMATS` совпадают по составу (проверено тестом).

## 3. Дефекты, найденные и исправленные в этом проходе

1. Неизвестный `aspect` выводился строчными буквами — исправлено на «Формат не определён».
2. Сообщение о пересоздании показывало ID исходника вместо созданного шаблона — исправлено.
3. `undo()` всегда писал «Отменено», даже при частичном откате — исправлено проверкой групп.
4. `module.json` четырёх методов содержали `4:5`/`5:6` без решения владельца — откатано.
5. Дедупликация `motion-converter` объединяла по `tpl+aspect`, не сравнивая `canvas` и не предупреждая о разном HTML — исправлено.
6. `source.motion` при конвертации терял совместимые поля — исправлено.

## 4. Решения и ограничения (нужно подтверждение владельца)

- **4:5 и 5:6 в `targetFormats`** не включены. Геометрия подтверждена матрицей (48/48, кадр и границы корректны), но композиция `contact` в 4:5 и 5:6 визуально слабая (`chk/shots/`). Варианты: (а) включить как «геометрия подтверждена, визуально требует проверки»; (б) не включать до доработки. Сейчас — (б).
- **Пересоздание без записанного метода** отказывает с причиной (раньше подставлялся метод). Это следствие VI.9 («не угадывать»). Для старых связей без `method` пользователь должен выбрать метод вручную.
- **Удаление** предлагается для структурно неполных записей (категория B, уверенность не ниже средней). Устаревшие конверсии (A) и метаданные (C) не удаляются. Пользователь может снять флажок перед удалением.
- **`sandbox_ui`** в архиве не включён (ждёт подтверждения).
- **Открытые вопросы, без ответа**: копия «в стиль» (объединять по HTML или отдельно); эталон поставки (1920×1080 или 1280×720); AE-атрибуты; Motion Studio; блок «Формат» в JSON для ИИ.
- `motion-converter.js`: проверка выполнялась в браузере через `window.SB_motionExporter`; число папок модулей (19) и число зарегистрированных методов совпадают. Отдельного расхождения не найдено.
- `adaptation-modules/README.md` устарел (описывает 4 метода) — не переписывался.

## 5. Не проверено (нужно проверить вручную)

- **Electron не запускался.** Все проверки — в Chromium (Playwright) по HTTP. Не заявлять Electron как проверенный.
- Реальные скачивания пакета и резервной копии: проверено наличием события скачивания и содержимым пакета; содержимое резервной копии не разбиралось подробно.
- Откат полного архива через `restoreArchive` (Undo после восстановления архива) — проверен откат `pushUndo`/`undo` по группам, а не полный цикл «архив → восстановление → Undo» с файлом.
- Копирование отчёта в буфер обмена (`navigator.clipboard`) — в headless-режиме не проверялось.
- Визуальный вид инспектора и капсул в Electron-окне; плотность списка при большом числе записей.
- Ответы реальной нейросети на пакет — не проверялись; проверены только структурные правила импорта.
- Ручная проверка 4:5/5:6 `contact` (композиция).
