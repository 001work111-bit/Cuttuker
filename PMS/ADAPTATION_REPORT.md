# Адаптация шаблонов в Pano Montage Studio — отчёт

## Что сделано
- **Общая система модулей.** `js/adaptation/recompose-core.js`, `adaptation-modules/{smart,split,compact,fit}/` и `adaptation-modules/_shared/css-groups.js` — побайтно как в Sandbox (15 файлов, включая README модулей). Проверка: `node tools/build-adaptation-manifest.js --verify <путь/к/Sandbox>`.
- **Загрузка.** `js/adaptation/adaptation-loader.js` подключает библиотеку обычными `<script src>` по `adaptation-modules/manifest.js`: сначала `_shared` (один раз), затем модули по порядку. Формат записей — как у Sandbox (`libraries[{rel}]`, `modules[{folder, rel, descriptor}]`). Загрузчик Pano переведён на `rel`. Без `eval`, `new Function`, `fetch`.
- **Манифест.** `tools/build-adaptation-manifest.js` — порт правил Sandbox `buildManifest`/`scanFolder`: рекурсивные `_`-библиотеки (глубина 8, только `.js`), модули с `module.json` + `module.js`, сортировка `localeCompare`. Проверка на совпадение с Sandbox: `node tests/adaptation/check-manifest-vs-sandbox.js <путь/к/Sandbox>` (запускает `Sandbox.buildManifest` с заглушкой electron, Sandbox не меняется).
- **Двойной загрузки нет.** Прямой `<script>` на `css-groups.js` из `index.html` удалён. Библиотека грузится только через манифест.
- **Слой Pano.** `js/adaptation/pano-adaptation.js`: пересчёт от исходника, кэш и очередь, связанные селекторы «Формат» и «Метод», Ctrl+колесо, метаданные, временный предпросмотр блока.
- **Инспектор шаблона (библиотека).** Секция «Адаптация»: предпросмотр сразу, «Обновить шаблон» (перезапись; у системного шаблона — версия в user.js), «Создать копию» (новый ID, `parentTemplateId`, метка «· формат · метод»).
- **Инспектор блока (таймлайн).** Секция «Адаптация»: предпросмотр в блоке и мониторе без записи в блок, «Применить», «Вставить после». «Сохранить как новый шаблон» переименовано в «Сохранить шаблон»; сохраняет формат, размеры, метод и исходник.
- **Модель.** Поле `adaptation` в шаблоне (`normalizeTemplateItem`, `templateDefinitionForEditor`) и в `templateMeta` блока (`makeTemplateBlock`). Монитор: `templateRenderHtml`; при предпросмотре запись из DOM отключена.
- **Стили.** Только существующая палитра Pano (`.adaptPreview`, `.adaptPreviewFrame`); новых цветов и кнопок нет.

## Поведение
- Форматы: 16:9, 9:16, 1:1, 4:3. Методы: smart, compact, split, fit (и любые новые модули с нужным `targetFormats`).
- Метод показывается только совместимый с форматом. При недоступности выбирается первый совместимый.
- Результат всегда строится от исходника (`adaptation.sourceHtml`). Повторная адаптация не строится на результате.
- Размеры дизайна = эталонный холст движка: 16:9 — 1920×1080, 9:16 — 1080×1920, 1:1 — 1080×1080, 4:3 — 1440×1080.
- «Вставить после»: копия с новым ID; исходный блок не меняется. Основной трек — последующие блоки сдвигаются. Абсолютные overlay — копия идёт за исходным, более поздние абсолютные блоки сдвигаются на длину копии.
- Ctrl+колесо над селектором: один шаг на щелчок. Накапливается `deltaY` до порога 60, пауза 160 мс после шага, сброс при смене направления или паузе > 260 мс. Без Ctrl поведение не меняется. Границы без цикла и без сброса.
- Undo/Redo: применение, вставка, сохранение и перезапись — отдельные шаги истории (`pushHistory` до, `commitHistory` после).

## Ограничения
0. **Предпросмотр блока не сбрасывается** при откате истории (`applySnapshot`) и закрытии инспектора блока. Предпросмотр действует, пока открыт инспектор того же блока. Решение не принято; отдельная правка не делалась.
1. **Обнаружение модулей в браузере.** `file://` не перечисляет папки. Новый модуль подхватывается после `node tools/build-adaptation-manifest.js`. Автоматического обнаружения произвольных папок нет. В Electron-сборке Sandbox сканирует папку сама; в Pano Electron не внедрялся по условию.
2. **Ошибки модуля.** Отсутствие `markup`, неверный `engineApi`, нет `module.js` и т. п. — модуль не подключается; причина в `PMS_ADAPTATION_LOADER.errors()`. Остальные модули работают.
3. **Тестовый модуль** `testcenter` (название «Тестовый пример (не метод)») в поставку не входит, только в проверочной копии `/tmp/modtest`. Пересоздаётся командой из `tests/adaptation/README.md`.
4. **Сохранение библиотеки.** В браузере записи файла нет: изменения шаблонов сохраняются в проекте, `user.js` — через экспорт (как и другие правки библиотеки).
5. **Служебные атрибуты.** При монтаже блока Pano дописывает `data-ms-node-id` и правит корневой узел. Поэтому сохранённый HTML блока побайтно может отличаться от «сырого» результата движка. Текст и структура совпадают (проверено в t3).
6. **Исходники 16:9.** `sourceFormats` = `["16:9"]`, потому что все шаблоны библиотеки 16:9. Для исходника 9:16 методов нет (это правило движка).
7. **Валидация форматов.** В движке 9:16, 1:1, 4:3 помечены `validated:false`. Матрица 4 метода × 4 формата × 9 шаблонов: на 4:3 для каждого метода по одному шаблону с предупреждением, структура не нарушена.
8. **Колесо.** Проверено синтетическими `WheelEvent` (deltaY, deltaMode, ctrlKey). Реальный тачпад и браузерный zoom на физическом устройстве не проверялись; zoom блокируется `preventDefault`.
9. **Правка текста после адаптации.** При повторном «Применить» приложение спрашивает подтверждение. Результат строится от исходника, поэтому правки текста блока пропадут.
10. **Существующий `new Function`.** В `js/templates/template-browser.js` (строка 52, загрузка `templates/*.js`) остался без изменений по условию «без несвязанных рефакторингов». Новый код `eval` и `new Function` не использует.

## Готовность общей библиотеки
- **Sandbox:** готова (регрессия 72/72, UI 18/24/31). README обновлён: `targetFormats`, `scenarios`, раздел про браузерную версию.
- **Pano:** готова для браузерного режима (`file://`). Новый модуль подключается только папкой в `adaptation-modules/` и пересборкой манифеста; основной код Pano не меняется (t4). Electron и способ запуска не менялись.
- **Общее ядро:** движок и модули побайтно совпадают с Sandbox.
