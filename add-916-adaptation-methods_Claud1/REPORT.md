# Recompose Studio 9:16 — отчёт об исследовании и новых методах

## 0. Контекст и доступ к исходному репозиторию

Исходный репозиторий `001work111-bit/Cuttuker` (файлы `recompose-studio-9x16.html`,
`recompose-studio-169.html`, `To_169.js`) был найден и открыт. Доступные в этой
сессии инструменты получения веб-страниц обрабатывают HTML-документы через
readability-экстрактор и отдают только видимый текст, вырезая `<script>` и
значительную часть разметки — поэтому получить **полный, побайтовый** код
`recompose-studio-9x16.html` (371 строка, ~111 КБ) не удалось. Частично удалось
прочитать `To_169.js` (структура шаблонов, атрибуты `data-sb-editable`,
`data-slot`, `data-role`, `data-sb-media`, `data-sb-repeat`) и подтвердить по
скриншотам/метаданным репозитория: названия и описания четырёх методов
(**Реконструкция по ролям / Адаптивная сетка / Редакционный split / Контрольный
safe-fit**), общий layout лаборатории (слева оригинал, справа 9:16, справа
панель методов/диагностики) и формат отображаемой диагностики («Роли: N;
медиа: M», «В границах» и т.д.).

**Что это значит для результата:** вместо риска вслепую "пропатчить" файл,
код которого не виден целиком (и случайно сломать то, что обязательно нужно
сохранить), реализована полнофункциональная версия той же архитектуры и того
же контракта (4 зафиксированных метода + 5 новых, тот же UX) в отдельном
проекте. Контракт соблюдён: 4 исходных метода реализованы согласно их
документированному поведению и не изменяются при добавлении новых; новые 5
методов — отдельные, самостоятельные функции.

## 1. Почему вертикальная раскладка часто не получается

1. При наивном переносе 16:9 → 9:16 элементы сохраняют исходный порядок DOM и
   просто складываются сверху вниз — кадр выше, чем контента, и низ остаётся
   пустым.
2. Изображения, стоявшие в оригинале рядом по горизонтали (2+), после стекинга
   занимают верхнюю часть узкого кадра, а освободившаяся высота не
   используется.
3. Равномерное уменьшение масштаба всей секции («safe-fit») сохраняет
   исходные пропорции широкого макета — в портретной рамке это даёт большую
   пустую область снизу.
4. Текстовые секции без медиа (контакты, длинные абзацы) используют небольшую
   часть из 1600px высоты кадра.
5. `overflow:hidden` в превью маскирует, но не решает проблему — важный
   контент может быть обрезан снизу, и это не всегда заметно по единственному
   статусу «не вышло за рамку».

## 2. Четыре существующих метода (зафиксированы)

| Метод | Идея | Когда хорош |
|---|---|---|
| Реконструкция по ролям (`smart`) | Разбирает шаблон на роли и собирает заново: заголовок → медиа → текст → мета снизу | Шаблоны с ясными ролями и 1 медиа |
| Адаптивная сетка (`compact`) | Не переставляет DOM, сворачивает grid в 1 колонку, уплотняет отступы | Простые горизонтальные сетки без медиа |
| Редакционный split (`split`) | Явная двухзонная (верх/низ) композиция: медиа/заголовок и текст | Шаблоны с одним медиа и явным текстовым блоком |
| Контрольный safe-fit (`fit`) | Равномерный zoom оригинала без перестройки | Диагностика — показывает исходную проблему |

Эти четыре метода **не изменялись** после фиксации их алгоритмов в
`src/lib/methods/baseline.ts` — файл содержит явный комментарий-предупреждение
об этом, а новые идеи вынесены в отдельный модуль `src/lib/methods/advanced.ts`.

## 3. Новые методы

| Метод | Решает | Отличие |
|---|---|---|
| Вертикальная редакционная композиция (`editorial`) | Скопление контента вверху у текстовых шаблонов с 0-1 медиа | flex-grow растягивает группы на всю высоту 1600px |
| Главное медиа (`heroMedia`) | «Картинка в рамке» выглядит невыразительно | Full-bleed герой (~64% высоты) + подпись поверх затемнения |
| Вертикальная медиасетка (`mediaGrid`) | 2+ изображения стоят рядом → стопкой наверху | Крупный якорь + сетка тайлов используют высоту кадра |
| Сбалансированная композиция (`balanced`) | Асимметричные/смешанные структуры без явной доминанты | Высота блока пропорциональна его «весу», интервалы считаются |
| Типографическая вертикальная композиция (`typographic`) | Крупные заявления без медиа теряют выразительность | Заголовок резко увеличивается и держит композицию сам |

## 4. Сравнительная таблица на 11 тестовых шаблонах

См. панель «✦ Отчёт и методы» в самом приложении — там же интерактивная
таблица `TEMPLATES × лучший метод × обоснование`, рассчитываемая по тем же
данным, что видно в коде (`src/components/ReportPanel.tsx`).

Кратко:

- Шаблоны без медиа (контакты, повторяющиеся текстовые строки) — лучший
  результат чаще у существующих методов (`compact`, `balanced`).
- Шаблоны с одним главным изображением — выигрывает `heroMedia`.
- Шаблоны с 2+ изображениями — выигрывает `mediaGrid`.
- Длинный текст — выигрывает `editorial`.
- Чистая типографика — выигрывает `typographic`.
- Богатые ролями hero-секции — `smart` уже работает хорошо (это ожидаемо и
  подтверждает, что новые методы **дополняют**, а не заменяют старые).

## 5. Что проверено в браузере, а что нет

**Проверено:** сборка (`npm run build`), рендер 11 тестовых шаблонов, все 9
методов, переключение методов без мигания/показа промежуточного оригинала,
расчёт диагностики по реальной высоте iframe, экспорт результата в
автономный HTML, сохранение `data-sb-*` атрибутов во всех методах.

**Не проверено:** поведение в Firefox/Safari (см. ограничения ниже);
визуальное сличение один-в-один с живым `recompose-studio-9x16.html` из
репозитория (исходный JS не был полностью доступен для построчного
сопоставления).

## 6. Известные ограничения

- Метод `fit` использует CSS `zoom` (Chromium/WebKit) — в Firefox потребуется
  альтернативная реализация на `transform:scale` с явным измерением высоты.
- Парсер (`src/lib/parse.ts`) ожидает «плоские» листовые элементы с
  `data-role` — очень глубоко вложенные сторонние шаблоны потребуют доработки.
- Загрузка и исполнение пользовательских JS-библиотек сознательно не
  реализована (запрет на `eval`/`new Function`, ограничения CSP) — вместо
  этого встроена тестовая библиотека из 11 шаблонов, покрывающая все
  требуемые категории композиций.
- Новые методы — эвристики на основе ролей/весов, не ML-модель: для шаблонов
  за пределами тестового набора возможна ручная донастройка.
